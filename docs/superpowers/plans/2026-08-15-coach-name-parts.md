# Coach Name Parts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register coaches with first, middle and last name exactly as participants are, and display them surname-first everywhere a coach's name appears.

**Architecture:** `coaches` gains the same three columns `participants` already has, and every surface stops reading a stored `full_name` in favour of a display name derived once on the server — the pattern participants already use via `toRosterParticipant`. That derivation moves into `lib/roster/names.ts` so the entry page, the admin pages and the export all build the same string from the same code. The column drop is staged across two migrations so the running deployment never selects a column that is gone.

**Tech Stack:** Next.js App Router (server components + server actions), Supabase (Postgres, RLS), Zod, vitest, Tailwind + shadcn/ui.

**Spec:** `docs/superpowers/specs/2026-08-15-coach-name-parts.md`

## Global Constraints

- **This is not the Next.js you know.** Per `AGENTS.md`, read the relevant guide under `node_modules/next/dist/docs/` before writing framework code. `AGENTS.md` is regenerated by `next dev`; commit it with your work if it shows as modified.
- Tests run with `npm test` (`vitest run`). Lint with `npm run lint`. Type-check with `npx tsc --noEmit`.
- Only `lib/**` pure logic is unit-tested. Pages, components and server actions have **no test harness** — do not add one; push logic worth testing into `lib/`.
- `npm run lint` reports exactly 3 pre-existing `react-hooks/set-state-in-effect` errors (`app/entry/EntryWizard.tsx`, `app/entry/SchoolPaperDialog.tsx`, `components/theme-toggle.tsx`). Leave them; a 4th is yours.
- Migrations are plain SQL under `supabase/migrations/`, numbered sequentially, applied by hand, and must be idempotent.
- The display format is exactly the participants' format: `"Last, First Middle"`, with the middle name omitted when absent and no trailing comma when a part is empty. Build it in one place; never re-implement it.
- Coaches keep gender, their per-school roster, their entry links, and the submission lock's coverage. Nothing else about them changes.
- Comments explain *why*, not *what*, in prose.

### Task 1: Migration — the three columns

**Files:**
- Create: `supabase/migrations/0013_coach_name_parts.sql`

**Interfaces:**
- Produces: `coaches.first_name text not null`, `coaches.middle_name text`, `coaches.last_name text not null`; `coaches.full_name` nullable.

Read `supabase/migrations/0004_roster_and_paper_gate.sql` first — it defines both `participants` and `coaches`, and the three new columns must match `participants`' exactly.

- [ ] **Step 1: Write the migration**

```sql
-- Press Link: coaches are registered the way participants already are.
--
-- A single "Complete name" field left every school free to type "Ana Dela Cruz"
-- for a participant and "Dela Cruz, Ana" for that person's coach, which produced
-- two different orderings in the same export. The three parts fix the ordering
-- at the point of entry instead of guessing at it afterwards.
--
-- Additive on purpose: the running deployment still selects full_name by name,
-- so it stays (nullable) until 0014 drops it after this code ships.

alter table coaches add column if not exists first_name text;
alter table coaches add column if not exists middle_name text;
alter table coaches add column if not exists last_name text;

-- The division office reports no coaches registered yet, so this is expected to
-- touch nothing. It is written anyway, and deliberately does not guess at word
-- boundaries: splitting "Juan Dela Cruz" on spaces yields the surname "Cruz"
-- and a middle name of "Dela", silently. Putting the whole string in last_name
-- is lossless and visibly wrong, which a school can correct in seconds.
update coaches
  set last_name = coalesce(last_name, full_name),
      first_name = coalesce(first_name, '')
  where full_name is not null and last_name is null;

-- Any row that arrived without either name is not worth a not-null violation.
update coaches set first_name = '' where first_name is null;
update coaches set last_name = '' where last_name is null;

alter table coaches alter column first_name set not null;
alter table coaches alter column last_name set not null;

-- The new code inserts the three parts and never writes full_name, so the old
-- column cannot stay NOT NULL or every insert fails between this migration and
-- the deploy.
alter table coaches alter column full_name drop not null;
```

Confirm every statement is re-runnable: `add column if not exists`, the updates are idempotent by their `where` clauses, and `set not null` / `drop not null` are no-ops when already in that state. Report what you checked.

Do **not** apply the migration — you have no database access.

### Task 2: One surname-first formatter

**Files:**

- [ ] **Step 1: Write the failing tests**

Create `lib/roster/names.test.ts`:

```ts
import { describe, expect, it } from "vitest";

import { surnameFirst } from "./names";

describe("surnameFirst", () => {
  it("puts the surname first, then the given names", () => {
    expect(
      surnameFirst({ first_name: "Ana", middle_name: "Mercado", last_name: "Dela Cruz" })
    ).toBe("Dela Cruz, Ana Mercado");
  });

  it("omits the middle name when there is none", () => {
    expect(surnameFirst({ first_name: "Ana", middle_name: null, last_name: "Dela Cruz" })).toBe(
      "Dela Cruz, Ana"
    );
  });

  it("treats an empty middle name as absent", () => {
    expect(surnameFirst({ first_name: "Ana", middle_name: "", last_name: "Dela Cruz" })).toBe(
      "Dela Cruz, Ana"
    );
  });

  it("leaves no dangling comma when only a surname is on file", () => {
    expect(surnameFirst({ first_name: "", middle_name: null, last_name: "Dela Cruz" })).toBe(
      "Dela Cruz"
    );
  });

  it("leaves no dangling comma when only given names are on file", () => {
    expect(surnameFirst({ first_name: "Ana", middle_name: null, last_name: "" })).toBe("Ana");
  });

  it("returns an empty string when nothing is on file", () => {
    expect(surnameFirst({ first_name: "", middle_name: null, last_name: "" })).toBe("");
  });
});
```

The last three cases matter because `0013` can leave a coach with an empty
`first_name`, and a name rendering as `", Dela Cruz"` in the export would be a
visible defect.

- [ ] **Step 2: Run the tests to verify they fail**

Run: `npx vitest run lib/roster/names.test.ts`
Expected: FAIL — the module does not exist. Capture the literal output.

- [ ] **Step 3: Write the module**

Create `lib/roster/names.ts`:

```ts
/** The name columns `participants` and `coaches` share. */
export interface NameParts {
  first_name: string;
  middle_name: string | null;
  last_name: string;
}

/**
 * "Dela Cruz, Ana Mercado" — the order the division office lists people in.
 *
 * Built on the server and passed down as a string, so no component re-derives
 * it and no two surfaces can disagree about the format. Empty parts drop out
 * rather than leaving a dangling comma: a coach migrated from the old single
 * name field has no first name until its school fills one in.
 */
export function surnameFirst(parts: NameParts): string {
  const given = [parts.first_name, parts.middle_name].filter(Boolean).join(" ");
  return [parts.last_name, given].filter(Boolean).join(", ");
}
```

Run: `npx vitest run lib/roster/names.test.ts`
Expected: PASS, 6 tests.
